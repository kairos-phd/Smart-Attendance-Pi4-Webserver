# Database

The finalized MVP Firestore contract is documented in:

`docs/FIRESTORE_DATA_MODEL.md`

Firebase project: `sicccc-30fed`
Firestore database: `(default)` in `asia-southeast1`
Deployment timezone: `Asia/Ho_Chi_Minh`

## Shared collections

- `accounts`: dashboard/mobile login profiles linked to Firebase Authentication
- `usernames`: unique username reservations
- `users`: enrolled face-recognition profiles
- `attendance`: recognized attendance events
- `unknown_events`: unknown-person event metadata
- `cameras`: status of each of the two cameras
- `devices`: status of the Raspberry Pi transport and laptop AI service
- `system_logs`: optional trusted-service diagnostics

The web and mobile applications use these same collections. They must not create competing data models.

## Storage decision

Firebase Storage is optional, not required for the MVP. Face images may remain on the laptop. Firestore must never contain image binaries, base64 images, or local filesystem paths.

## Data ownership

- Web/mobile clients read authorized dashboard data.
- Account signup creates only the caller's `accounts` profile and username reservation.
- The laptop FastAPI/AI service writes users, attendance, unknown events, cameras, devices, and logs through the Firebase Admin SDK.
- The Raspberry Pi transports sampled camera data to the laptop and maintains a local retry queue.
